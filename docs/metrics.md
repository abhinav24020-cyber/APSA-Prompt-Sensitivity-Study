# APSA Metrics Reference

**Project:** Adversarial Prompt Sensitivity Analysis (APSA)  
**Version:** Phase 5  
**Date:** September 2026  
**Source module:** `src/apsa/metrics/`

---

## Overview

This document defines every metric used in the APSA project, including:

- **Input Distance Metrics** — how far apart two prompts P and P′ are.
- **Output Distance Metrics** — how far apart two model responses Y and Y′ are.
- **Composite Divergence** — a weighted combination of output distances.
- **Sensitivity Coefficient** — the ratio of output change to input change.

Mathematical notation is kept consistent across all sections and source modules.

---

## 1. Notation

| Symbol | Meaning |
|--------|---------|
| P | Original (baseline) prompt string |
| P′ | Perturbed prompt string |
| \|P\| | Number of characters in P |
| \|P_w\| | Number of word-tokens in P |
| E(P) | Embedding vector of P from a sentence embedding model |
| M | Target LLM model |
| Y = M(P) | Output generated by M for prompt P |
| Y′ = M(P′) | Output generated by M for perturbed prompt P′ |

## 2. Input Distance Metrics

> **Source module:** `src/apsa/metrics/input_distance/`

All six Phase-5 metrics are implemented in `lexical.py` and returned together as a frozen `LexicalDistanceResult` dataclass.

### 2.1 Character-Level Levenshtein Distance

**Definition:**

$$d_{\text{char}}(P, P') = \text{edit}(P, P')$$

The minimum number of single-character **insertions**, **deletions**, or **substitutions** required to transform P into P′, computed by the Wagner-Fischer dynamic programming algorithm.

**Complexity:** O(|P| × |P′|) time, O(min(|P|, |P′|)) space.  
**Range:** d_char ∈ {0, 1, 2, …, max(|P|, |P′|)}.  
**Implementation:** `LexicalDistanceResult.char_levenshtein` (int)

```
edit("kitten", "sitting") = 3
  kitten → sitten  (k→s)
  sitten → sittin  (e→i)
  sittin → sitting (ε→g)
```

---

### 2.2 Normalized Character Distance

**Definition:**

$$d_{\text{char\_norm}}(P, P') = \frac{d_{\text{char}}(P, P')}{\max(|P|, |P'|)}$$

Scales the raw edit distance to [0, 1] by dividing by the length of the longer string.  
The `max(1, ·)` guard prevents division by zero when both strings are empty.

**Range:** d_char_norm ∈ [0, 1].  
**Boundary conditions:**
- d_char_norm = 0 iff P = P′
- d_char_norm = 1 iff one string is empty and the other is non-empty

**Implementation:** `LexicalDistanceResult.char_levenshtein_normalized` (float, rounded to 6 d.p.)

> [!NOTE]
> This metric is the primary budget check against `EpsilonBudget.lexical_char_normalized` (default: 0.10) in `apsa.config.schema`. No hard threshold is applied inside the metric itself; the caller is responsible for any threshold comparison.

---

### 2.3 Word-Level Edit Distance

**Definition:**

$$d_{\text{word}}(P, P') = \text{edit}(P_w, P'_w)$$

Same Levenshtein recurrence as §2.1, but the atoms are **word-tokens** rather than characters.

Tokenization rule: lowercase, keep alphanumeric + apostrophe sequences and individual punctuation marks as separate tokens (regex: `[a-zA-Z0-9']+|[^\s\w]`).

**Range:** d_word ∈ {0, 1, 2, …, max(|P_w|, |P′_w|)}.  
**Implementation:** `LexicalDistanceResult.word_levenshtein` (int)

**Example:**

```
"compute the value" → "calculate the value"
P_w  = ["compute", "the", "value"]
P'_w = ["calculate", "the", "value"]
d_word = 1  (one word substitution)
```

---

### 2.4 Changed-Word Count

**Definition:**

$$n_{\text{words\_changed}}(P, P') = d_{\text{word}}(P, P')$$

Each edit operation at the word level (insertion, deletion, or substitution) counts as one changed word. This metric equals `word_levenshtein` and is exposed under a semantically descriptive field name for clarity in downstream reporting.

**Implementation:** `LexicalDistanceResult.num_words_changed` (int)

---

### 2.5 Changed-Character Count

**Definition:**

$$n_{\text{chars\_changed}}(P, P') = d_{\text{char}}(P, P')$$

Raw character-level edit distance (same value as §2.1), exposed under a descriptive name that emphasizes *how many characters changed* rather than the algorithmic metric name.

**Implementation:** `LexicalDistanceResult.num_chars_changed` (int)

---

### 2.6 Percentage of Prompt Changed

**Definition:**

$$\text{pct\_changed}(P, P') = d_{\text{char\_norm}}(P, P') \times 100$$

Human-readable representation of the normalized character distance expressed as a percentage.

**Range:** pct_changed ∈ [0, 100].  
**Implementation:** `LexicalDistanceResult.pct_prompt_changed` (float, rounded to 4 d.p.)

---

### 2.7 Semantic Input Distance

> **Source module:** `src/apsa/metrics/input_distance/semantic.py`

**Definition:**

$$D_{\text{semantic}}(P, P') = 1 - \text{semantic\_similarity}(P, P')$$

where the default similarity function is **cosine similarity**:

$$\text{semantic\_similarity}(P, P') = \cos(E(P), E(P')) = \frac{E(P) \cdot E(P')}{\|E(P)\| \cdot \|E(P')\|}$$

Therefore:

$$D_{\text{semantic}}(P, P') = 1 - \frac{E(P) \cdot E(P')}{\|E(P)\| \cdot \|E(P')\|}$$

**Range:**
- D_semantic ∈ [0, 2] for arbitrary real-valued embedding vectors.
- D_semantic ∈ [0, 1] for **unit-norm** embeddings (e.g., `sentence-transformers` with `normalize_embeddings=True`), which is the configured default.

**Boundary conditions:**
- D_semantic = 0 iff E(P) and E(P′) point in the same direction (semantically equivalent).
- D_semantic = 1 iff E(P) ⊥ E(P′) (completely unrelated meaning, for unit-norm embeddings).
- D_semantic = 2 iff E(P) = −E(P′) (anti-parallel; semantically opposite).

**Implementation:** `SemanticDistanceCalculator` returns a frozen `SemanticDistanceResult` with fields `cosine_distance`, `cosine_similarity`, and `embedding_model`.

#### 2.7.1 Modular Embedding Interface

The embedding model E is injected via the `EmbeddingModel` abstract interface:

```python
class EmbeddingModel(ABC):
    @property
    @abstractmethod
    def model_name(self) -> str: ...

    @abstractmethod
    def encode(self, texts: list[str]) -> list[list[float]]: ...
```

The default implementation is `SentenceTransformerEmbedder` using `all-mpnet-base-v2`.

**To swap the embedding model**, implement `EmbeddingModel` and pass it to `SemanticDistanceCalculator`:

```python
class OpenAIEmbedder(EmbeddingModel):
    @property
    def model_name(self) -> str:
        return "text-embedding-3-small"
    def encode(self, texts: list[str]) -> list[list[float]]:
        # call openai.embeddings.create(...)
        ...

calc = SemanticDistanceCalculator(OpenAIEmbedder())
```

#### 2.7.2 Model Selection

The modular metric API defaults to `all-mpnet-base-v2`. The lightweight pilot
uses `sentence-transformers/all-MiniLM-L6-v2` unless overridden with
`--semantic-model`. The selected model ID is recorded in each run manifest and
semantic-distance record. Changing embedding models can change the measured
distances and should be treated as a change in experimental configuration.

| Property | Value |
|----------|-------|
| Dimensionality | 768 |
| Output normalization | Yes (unit-norm vectors) |
| Training data | 1B+ sentence pairs |
| STS-B Spearman ρ | ≈ 0.86 |
| HuggingFace ID | `sentence-transformers/all-mpnet-base-v2` |

> [!IMPORTANT]
> **No semantic threshold is applied within this module.** The raw `cosine_distance` value is always returned. Any threshold (e.g., D_semantic < 0.05 → "semantically minimal perturbation") is a **research parameter** that must be documented in the experiment configuration (`EpsilonBudget.semantic_cosine` in `apsa.config.schema`, default: 0.05). Callers are responsible for applying and documenting any such threshold.

#### 2.7.3 Batch Computation

`SemanticDistanceCalculator.compute_batch()` accepts a list of `(original, perturbed)` pairs and encodes all unique strings in a **single forward pass**, avoiding redundant inference:

```python
results = calc.compute_batch([
    ("What is AI?", "What is artificial intelligence?"),
    ("Compute X.", "Calculate X."),
])
```

### 2.8 Syntactic Input Distance (Not Implemented)

> **Source module:** `src/apsa/metrics/input_distance/syntactic.py`

**Definition:**

$$d_{\text{syn}}(P, P') = \frac{\text{TED}(T(P), T(P'))}{\max(|T(P)|, |T(P')|)}$$

where:
- T(P) is the dependency parse tree of P (produced by spaCy).
- TED is the All-Path Tree Edit Distance (APTED algorithm) — minimum-cost node insertions, deletions, and relabellings.
- |T(P)| is the number of nodes (tokens) in the tree.

**Range:** d_syn ∈ [0, 1].

> [!WARNING]
> `SyntacticDistanceCalculator.compute()` raises `NotImplementedError`. No tree
> edit distance is produced by the current implementation; the syntactic
> dimension therefore has zero weight in the configured composite and in the
> lightweight pilot analysis. The syntactic epsilon setting is retained only
> for future use and does not imply that this metric is available.

---

### 2.9 Composite Input Distance

**Provisional definition** (only applicable when a syntactic metric is actually implemented):

$$d_{\text{input}}(P, P') = \alpha \cdot d_{\text{char\_norm}}(P, P') + \beta \cdot D_{\text{semantic}}(P, P') + \gamma \cdot d_{\text{syn}}(P, P')$$

Configured weights (from `CompositeInputWeights` in `apsa.config.schema`):
- α (alpha_lexical) = 0.50
- β (beta_semantic) = 0.50
- γ (gamma_syntactic) = 0.00

The lightweight pilot evaluator uses these lexical-character and semantic
embedding weights when both measurements are present. It separately reports
the character-only ratio for comparison. Missing semantic input distances are
preserved as unavailable; they are not replaced with character distance.

## 3. Output Distance Metrics

> **Source module:** `src/apsa/metrics/output_distance/` (Phase 6+)

These metrics measure divergence between LLM outputs Y = M(P) and Y′ = M(P′).

### 3.1 Textual Output Distance

$$d_{\text{text\_out}}(Y, Y') \in [0, 1]$$

Normalized character-level edit distance between the two output strings (same formula as §2.2 applied to outputs).

### 3.2 Semantic Output Distance

$$d_{\text{sem\_out}}(Y, Y') = 1 - \cos(E(Y), E(Y'))$$

Cosine distance between sentence embeddings of the two outputs. Uses the same `EmbeddingModel` interface as §2.7.

### 3.3 Functional / Task-Level Change

$$\Delta f_{\text{task}}(Y, Y') \in [0, 1]$$

Task-specific binary or graded measure:
- **Mathematical reasoning**: 1 if the final numerical answer differs, 0 otherwise.
- **Code generation**: 1 − pass@1 agreement (test suite execution).
- **Closed QA**: 1 − token-level F1 score.
- **Summarization**: 1 − ROUGE-L F1 score.

---

## 4. Composite Output Divergence

> **Source module:** `src/apsa/metrics/composite.py`

**Definition:**

$$D_{\text{out}}(Y, Y') = w_1 \cdot d_{\text{text\_out}}(Y, Y') + w_2 \cdot d_{\text{sem\_out}}(Y, Y') + w_3 \cdot \Delta f_{\text{task}}(Y, Y')$$

Constraint: w₁, w₂, w₃ ≥ 0.

Default weights (from `MetricWeights` in `apsa.config.schema`):
- w₁ (w1_textual) = 0.33
- w₂ (w2_semantic) = 0.34
- w₃ (w3_functional) = 0.33

**Implementation:** `CompositeOutputDivergence.compute(d_text_out, d_sem_out, delta_f_task)`

---

## 5. Sensitivity Coefficient

> **Source module:** `src/apsa/analysis/sensitivity.py`

**Definition:**

$$\mathcal{S}(P, P'; M) = \frac{D_{\text{out}}\bigl(M(P), M(P')\bigr)}{d_{\text{input}}(P, P') + \eta}$$

where:
- η > 0 is a smoothing constant preventing division by zero (default: η = 10⁻⁴).
- The modular analyzer uses the input distance supplied in each record. The
  lightweight pilot reports a character-only ratio and, when available, a
  separate composite lexical/semantic ratio; output distance in that pilot is
  normalized character distance, not the composite output metric in §4.

**Interpretation:**
- S ≫ 1.0 → a large measured output-string change relative to the recorded input-distance scale; not, by itself, evidence of vulnerability or causality.
- S ≈ 1.0 → proportional response: output change scales with input change.
- S ≪ 1.0 → robust: input was changed but output barely moved.

> [!NOTE]
> η = 10⁻⁴ stabilizes the ratio but does not prevent large scores for very small input changes. Identical-prompt controls are used to estimate natural output variation. If a different value is chosen, document it in the experiment configuration.

## 6. Epsilon Budget (Perturbation Constraints)

The valid perturbation space P(P, ε) is defined by the `EpsilonBudget` in `apsa.config.schema`:

| Constraint | Config field | Default | Metric used |
|------------|-------------|---------|-------------|
| Normalized char edit ≤ ε_lex | `lexical_char_normalized` | 0.10 | §2.2 |
| Semantic cosine distance ≤ ε_sem | `semantic_cosine` | 0.05 | §2.7 |
| Normalized TED ≤ ε_syn | `syntactic_ted_normalized` | Not applied (metric unavailable) | §2.8 |

A perturbation is filtered only by constraints whose metrics are available and
configured. The syntactic constraint is not currently evaluated:

$$P' \in \mathcal{P}(P, \boldsymbol{\varepsilon}) \iff d_{\text{char\_norm}}(P, P') \le \varepsilon_{\text{lex}} \;\land\; D_{\text{semantic}}(P, P') \le \varepsilon_{\text{sem}}$$

> [!CAUTION]
> The ε_sem = 0.05 threshold corresponds to cosine **distance**, not similarity.
> It is a configured analysis budget, not a validated semantic-equivalence
> threshold. Embedding similarity is not a substitute for human semantic
> adjudication.

## 8. Quick-Start Examples

```python
from apsa.metrics.input_distance import LexicalDistanceCalculator, SemanticDistanceCalculator

# --- Lexical metrics (no external dependencies) ---
lex = LexicalDistanceCalculator()
r = lex.compute(
    original="Explain the concept of entropy in thermodynamics.",
    perturbed="Describe the notion of entropy in thermodynamics.",
)
print(f"Char edit distance:  {r.char_levenshtein}")
print(f"Normalized:          {r.char_levenshtein_normalized:.4f}")
print(f"Word edit distance:  {r.word_levenshtein}")
print(f"Words changed:       {r.num_words_changed}")
print(f"Chars changed:       {r.num_chars_changed}")
print(f"% changed:           {r.pct_prompt_changed:.2f}%")

# --- Semantic distance (requires sentence-transformers) ---
sem = SemanticDistanceCalculator()   # defaults to all-mpnet-base-v2
r2 = sem.compute(
    original="Explain the concept of entropy in thermodynamics.",
    perturbed="Describe the notion of entropy in thermodynamics.",
)
print(f"Cosine distance: {r2.cosine_distance:.4f}")
print(f"Embedding model: {r2.embedding_model}")
```

## 10. Output Deviation Metrics

> **Source module:** `src/apsa/metrics/output_distance.py`

These metrics measure how a model's output changes when the input prompt is perturbed.

### 10.1 Exact Match
Binary indicator if the original output exactly matches the perturbed output (ignoring leading/trailing whitespace).

### 10.2 Normalized String Similarity
$$1 - \frac{d_{\text{char}}(Y, Y')}{\max(|Y|, |Y'|)}$$
Similarity based on Levenshtein distance.

### 10.3 Character-level Distance
Raw Levenshtein edit distance between output strings.

### 10.4 Token-level Distance
Jaccard distance between the sets of whitespace-separated tokens in the outputs:
$$d_{\text{token}} = 1 - \frac{|T(Y) \cap T(Y')|}{|T(Y) \cup T(Y')|}$$

### 10.5 Semantic Similarity
Cosine similarity between sentence embeddings of the outputs using `sentence-transformers`.

### 10.6 Semantic Output Distance
$$D_{\text{output}} = 1 - \text{semantic\_similarity}(Y, Y')$$

## 11. Correctness Flips

For tasks with objectively correct answers, we track task-level performance degradation or improvement.

**Classification Tasks:**
- `correct -> incorrect`
- `incorrect -> correct`
- `same class`

**Mathematical/Reasoning Tasks:**
- `correct -> incorrect`
- `incorrect -> correct`
- `same answer`

> **IMPORTANT**: Textual difference (high edit distance) does not automatically mean a meaningful behavioral difference. For open-ended generation tasks, qualitative evaluation and semantic output distance ($D_{\text{output}}$) should be weighted more heavily than exact string matching.

## 12. Robust Sensitivity and Deviation Analysis

> **Source module:** `src/apsa/analysis/sensitivity.py`

While the pure Sensitivity Coefficient ($S$) provides a raw normalized measure, it can be overly sensitive to infinitesimal input changes. Therefore, our primary research objective is formulated as a constrained optimization problem rather than a simple unconstrained maximization.

### 12.1 Primary Objective Formulation

Maximize the output deviation ($D_{\text{output}}$) subject to a semantic budget constraint ($\epsilon_{\text{sem}}$) on the input:

$$
\max_{P'} D_{\text{output}}(M(P), M(P')) \quad \text{subject to} \quad D_{\text{semantic}}(P, P') \le \epsilon_{\text{sem}}
$$

This ensures that we only highlight adversarial perturbations that genuinely alter the model's behavior without fundamentally rewriting the core meaning of the prompt.

### 12.2 Auxiliary Statistical Measurements

To provide a complete picture of a model's stability, the analysis module computes several aggregate statistics over experimental runs:

1. **Absolute Output Deviation**: The raw $D_{\text{output}}$ for a given pair.
2. **Normalized Output Deviation**: $D_{\text{output}} / \max(D_{\text{output}})$, bounding the deviation to $[0, 1]$.
3. **Output Deviation per Unit Input Change**: Effectively the Sensitivity ratio $S = \frac{D_{\text{output}}}{D_{\text{input}} + \epsilon}$.
4. **Mean/Median Output Deviation**: Central tendencies of model instability.
5. **Confidence Intervals**: Calculated via the t-distribution standard error to estimate population variance.

### 12.3 Cohort Analysis
The module implements dynamic grouping functions to find:
- **Highest Sensitivity Cases**: Individual $(P, P')$ pairs exposing maximum instability.
- **Highest Sensitivity per Model**: Identifying the least robust LLMs.
- **Highest Sensitivity per Task**: Identifying which domains (e.g., coding vs logic) are most brittle.
- **Highest Sensitivity per Perturbation**: Identifying which types of noise (e.g., typos vs synonym swaps) are most damaging.
